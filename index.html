Migration Strategy

  • Assessment and inventory of existing AWS Glue jobs, dependencies, schedules and source/target interfaces.
  • Mapping Glue ETL logic into reusable PySpark and SQL transformation components.
  • Conversion of legacy transformation patterns into Databricks-native pipelines and Delta Lake tables.
  • Parameterisation and metadata-driven design to reduce duplicated code and simplify onboarding of new datasets.
  • Parallel validation of source and target datasets using record counts, control totals, reconciliation and data-quality checks.

Ingestion Architecture

  • Designed incremental ingestion patterns for cloud object storage using Auto Loader / cloudFiles.
  • Handled schema inference, schema evolution, checkpoints, rescued data and incremental processing.
  • Integrated structured and semi-structured data, including JSON, CSV, Parquet and API-driven sources.
  • Designed batch and streaming ingestion patterns according to latency, volume and operational requirements.
  • Used Delta Lake as the reliable target layer for downstream transformations and analytics.

Medallion Architecture

  • Bronze: raw/source-aligned ingestion with auditability and replay capability.
  • Silver: validated, cleansed, standardised and conformed datasets.
  • Gold: business-ready analytical models and curated data products.
  • Designed dependencies so downstream layers can be rebuilt from governed upstream data.
  • Applied data-quality rules at transformation boundaries to improve trust in analytics.

DLT / Lakeflow Pipelines

  • Designed declarative pipelines for dependency-aware data transformations.
  • Applied expectations and data-quality checks to validate pipeline outputs.
  • Used streaming tables and materialized-view patterns where appropriate.
  • Configured pipeline execution, dependencies, monitoring and operational recovery.
  • Structured pipelines into reusable Bronze, Silver and Gold flows.

Databricks Cluster & Compute Configuration

  • Selected job versus interactive compute based on workload and operational needs.
  • Configured appropriate Databricks Runtime versions and Spark settings for production workloads.
  • Considered worker sizing, autoscaling, driver capacity and workload characteristics.
  • Used cluster policies to standardise compute configuration and control platform usage.
  • Optimised compute utilisation by separating ETL, development and workload-specific processing patterns.

Data Optimisation

  • Reduced small-file impact through compaction and Delta maintenance strategies.
  • Applied partitioning where it suited access patterns and considered clustering/data-layout strategies for evolving workloads.
  • Used OPTIMIZE and, where appropriate, Z-Ordering or modern liquid-clustering approaches.
  • Tuned Spark joins, partition sizing, caching, shuffle behaviour and query plans.
  • Reviewed execution plans and Spark UI metrics to identify bottlenecks.

Migration Engineering Checklist

A practical view of the engineering controls applied during a production migration.

✓ Source analysis — schema, volume, frequency and dependency assessment
✓ Incremental loads — watermarking, checkpoints and change-based processing
✓ Schema management — evolution, enforcement and controlled changes
✓ Data quality — expectations, reconciliation and exception handling
✓ Performance — Spark UI, query plans, partitions, joins and file layout
✓ Reliability — retries, restartability, idempotency and audit controls
✓ Security — Unity Catalog, access controls, secrets and governed access
✓ CI/CD — Git, Azure DevOps and controlled promotion across environments
✓ Monitoring — pipeline status, failures, data quality and operational metrics
✓ Cost control — right-sized compute, autoscaling and workload separation
